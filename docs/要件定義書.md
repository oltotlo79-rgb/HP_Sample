# QuickCRM コーポレートサイト リニューアル 要件定義書

最終更新: 2026-05-19
プロジェクトコード: `quickcrm-hp-renewal`

---

## 1. プロジェクト概要

### 1.1 背景
現行サイト ( https://quickcrm.site/ および ステージング https://quickcrm.stage-cmssv.awsv.jp/ ) は、白背景・テキスト中心の構成で情報は整理されているものの、視覚的訴求力と現代的なブランド表現に乏しい。コンタクトセンター向け CRM 製品「QuickCRM」(株式会社MITシステム研究所) の競合優位性 (高い自由度・柔軟な開発手法・包括的な機能) を直感的に伝えるため、コーポレートサイトを刷新する。

### 1.2 目的
1. ブランドイメージを刷新し、製品の先進性と業務適合性を視覚的に伝える
2. リード獲得 (資料ダウンロード／問い合わせ) を最適化する
3. 複数のデザイン方向性を並走検証できる「ABC 3案サンプル構成」を採用し、最終的な意思決定の素材とする
4. 将来的な機能追加・コンテンツ拡張に耐える保守容易なフロントエンド基盤を構築する

### 1.3 スコープ
- 本リポジトリでは **静的コーポレートサイト** (TOP + 3 サンプル × トップ + 機能紹介 2 ページ) を対象とする
- 管理画面、アプリケーション本体、CMS 連携は対象外 (将来拡張余地は確保する)

## 3. サイト全体構成

### 3.1 ルーティング (Next.js App Router)
```
/                         … メインランディング (3 サンプルへの導線)
/sample-a                 … サンプルA トップ (Organic Forest)
/sample-a/screen-builder  … 業務画面作成機能 (PPT slide 5)
/sample-a/management      … 管理機能 (PPT slide 6)
/sample-b                 … サンプルB トップ (Neo Mint Glass)
/sample-b/screen-builder
/sample-b/management
/sample-c                 … サンプルC トップ (Editorial Botanical)
/sample-c/screen-builder
/sample-c/management
```

### 3.2 メインページ ( `/` ) の必須要素
- QuickCRM ロゴ + キャッチコピー
- 「3 つのデザインサンプルを比較する」見出し
- 3 つのプレビューカード (各サンプルのキービジュアル + 一言コンセプト + 「サンプルを開く」CTA ボタン)
- 共通フッター (会社情報・電話 03-6891-1010・住所)

### 3.3 各サンプルトップページの必須要素
1. **Hero** ヒーロービジュアル + キャッチコピー + 主要 CTA
2. **製品コンセプト** (PPT slide 2 ベース: 「お客様自身で構築可能」訴求)
3. **3 つの強み** (PPT slide 3: 豊富な利用形態 / 柔軟な開発手法 / 手軽に導入可能)
4. **機能ハイライトへの導線** : 業務画面作成機能と管理機能の 2 ページに飛ぶカード
5. **フッター** (共通レイアウト・各サンプルの色調に合わせて装飾)

### 3.4 機能紹介ページ (PPT slide 5 = 業務画面作成機能)
- 見出し: 業務画面作成機能
- リード文: ノーコードで業務に合わせた画面を構築可能であることの説明
- 3 つの開発手法ブロック:
  1. **自由度の高い画面作成** : オブジェクト配置 → 設定 → 連携処理。トリガー (入力領域 / ボタン押下 / チェックボックス ON)・アクション (表示変更・色変更・値セット・計算処理・コピー・繰り返し)
  2. **テンプレートを用いた画面作成** : 案件処理／アウトバウンド／スケジュール処理／受注処理 のテンプレートを選択 → 画面上で調整
  3. **Excel を用いた画面作成** : Excel 設計書を読込 → 画面上で調整
- 各手法の特徴 (お客様自身で編集可能 / 業務に合わせた画面 / 高いカスタマイズ性 など) を Pill 形式で表示

### 3.5 機能紹介ページ (PPT slide 6 = 管理機能)
- 見出し: 管理機能
- リードコピー: 「必要な機能だけを選択可能」
- セクション構成:
  1. **アウトバウンド機能** : コールリスト管理 (作成処理・分配処理) / CTI 連携 (リスト検索・フィルター) / 自動架電 (プレビュー・プログレス・プレディクティブ) / 再架電予約・架電禁止登録・架電結果登録
  2. **データ管理機能** : データインポート (CSV/Excel 取込・画面編集・テーブル作成編集) / データエクスポート (CSV・外部システム連携・架電データ・顧客データ)
  3. **多様なレポート機能** : 架電結果表示 (オペレーター別/業務別/時間帯別) / ヒストリカルレポート / リアルタイムレポート
  4. **コミュニケーション機能** : メール送受信・SMS / センター内チャット / シートマップ
  5. **通話録音機能** (※通話録音システムとの連携が条件)

### 3.6 共通 UI 要素
- グローバルナビゲーション (sample 間切替リンク・「サンプル比較に戻る」)
- ページ上部のサンプル識別バッジ (Sample A / B / C)
- フッター (会社情報・電話番号・住所・コピーライト)
- パンくず (機能紹介ページのみ)

## 4. デザイン要件

### 4.1 共通方針
- メインカラーは緑系を基調とする (各サンプルでトーンを差別化)
- 3 サンプルは **明確に異なるデザイン哲学** を持ち、トーン・タイポ・レイアウト・アニメーションすべてで差別化する
- すべてリッチなアニメーションを適用しつつ `prefers-reduced-motion` で停止可能とする
- 商用フォントは使用せず Google Fonts またはセルフホスト可能なオープンフォントに限定

### 4.2 3 サンプル方向性
| サンプル | 略称 | 方向性 | 主軸カラー |
|---|---|---|---|
| A | Organic Forest | 自然・有機的・あたたかさ。波形・葉脈モチーフ。 | #1B4332 / #95D5B2 / #FAF3E0 |
| B | Neo Mint Glass | 近未来・サイバー・ガラスモーフィズム。 | #0A0E1A / #5EEAD4 / #06B6D4 |
| C | Editorial Botanical | スイス・エディトリアル・ミニマル・タイポ駆動。 | #2F5233 / #F7F4EC / #C9A227 |

詳細は `docs/plans/sample-*.md` を参照。

### 4.3 レスポンシブ
- ブレークポイント: 360 / 768 / 1024 / 1440 / 1920
- モバイルファースト設計
- タッチデバイスでは hover アニメーションを軽量代替に切替

### 4.4 アクセシビリティ
- WCAG 2.1 AA 準拠目標
- カラーコントラスト 4.5:1 以上 (テキスト / 重要 UI)
- キーボード操作で全ナビゲーション可能
- フォーカスリングを各サンプルのデザイントーンで再定義 (削除しない)
- `aria-label` / 見出しの階層を保ち、ランドマーク区切りを徹底

## 5. 技術要件

### 5.1 フロントエンド
- **言語**: TypeScript 5.x (`strict: true`)
- **フレームワーク**: Next.js 15.x (App Router)
- **スタイリング**: Tailwind CSS v4 + CSS Modules (一部・複雑なアニメーション用)
- **アニメーション**:
  - 共通: Framer Motion 11.x
  - Sample B: React Three Fiber + drei (パーティクル / 3D グリッド)
  - Sample C: GSAP + ScrollTrigger (スクラブアニメーション)
  - Lottie アニメーション (Sample A の葉モチーフ)
- **アイコン**: lucide-react
- **フォント**: `next/font` でセルフホスト
- **画像**: `next/image` ; Cloudflare Images を将来的に検討
- **品質ツール**: ESLint (next/core-web-vitals) + Prettier + TypeScript strict + Vitest (ユニット) + Playwright (E2E)

### 5.2 デプロイ・インフラ
- **ホスティング**: Cloudflare Workers
- **アダプタ**: `@opennextjs/cloudflare` (App Router + SSR/ISR を Workers 上で実行)
- **ビルド**: GitHub Actions または Cloudflare の Git 連携でビルド & デプロイ
- **環境**:
  - `production` : `quickcrm.site` (将来切替予定)
  - `preview` : ブランチ毎のプレビュー URL
- **DNS**: 既存ドメインの切替は要打合せ (本リポジトリ範囲外)

### 5.3 性能要件
- Lighthouse Performance 90+ (デスクトップ・モバイル両方を目標)
- LCP < 2.5s / CLS < 0.1 / INP < 200ms
- 重い 3D / Lottie はビューポート Intersection Observer で遅延読み込み
- 画像は WebP / AVIF + `next/image` の自動最適化

### 5.4 SEO
- 各ページに固有の `metadata` (title / description / OG / Twitter)
- 構造化データ (Organization / Product) を JSON-LD で埋め込み
- `sitemap.xml` / `robots.txt` を自動生成
- Canonical URL を設定

### 5.5 計測
- Cloudflare Web Analytics を採用 (Cookie 不要)
- 主要 CTA クリックはカスタムイベントとして送信 (将来拡張)

### 5.6 セキュリティ
- HTTPS 強制 (Cloudflare 側)
- セキュリティヘッダー: CSP / X-Content-Type-Options / Referrer-Policy / Permissions-Policy を Worker レベルで付与
- フォーム POST が発生する場合は CSRF トークン + reCAPTCHA を導入 (現フェーズでは静的フォームのみ)

## 6. コンテンツ要件

### 6.1 文章
- 一次情報は `00_QuickCRM_機能概要.pptx` を出典とする
- トーンは「丁寧 / です・ます調 / 業務担当者にも読みやすい」
- 各サンプルでキャッチコピーのみ世界観に合わせて差別化し、製品事実は変更しない

### 6.2 画像
- AI 画像生成 (codex / 画像系モデル) で内製する
- 各サンプルごとに必要な画像のサイズ・スタイル・配置場所を `docs/plans/sample-*.md` に明記
- すべての画像は `public/images/sample-{a|b|c}/` 配下に配置
- 写真風画像はフリー素材としてのライセンスではなく AI 生成物 (商用利用可能なモデルの規約に従う)

### 6.3 ロゴ
- 既存の QuickCRM ロゴ画像を使用 (要支給)
- ない場合は `public/brand/quickcrm-logo.svg` をプレースホルダで作成し、後で差替え

## 8. 受入基準
- メインページから 3 サンプルそれぞれに遷移できること

- 機能紹介ページの記載内容が PPT slide 5/6 と整合していること
- Lighthouse スコア 90+ をデスクトップで満たすこと
- `prefers-reduced-motion` で主要アニメーションが停止すること
- 全ページがキーボードのみで操作可能であること
- Cloudflare Workers にデプロイされ、独自プレビュー URL でアクセスできること
